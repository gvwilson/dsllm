# Learning Data Science with LLMs

Audience: Undergraduates two years into a degree. Some high-school Python,
unused for years. Want to make charts and trust their results. Already use
LLMs for writing and search. Worried about deskilling, job loss, and the
social and environmental costs of AI tools.

Each session is one hour. Each session uses a different example.

In sessions 1-6 the LLM writes all code. Learners focus on writing prompts,
running the code they receive, and interpreting the output. In sessions 7-12
learners begin reading what the LLM produced well enough to catch errors and
understand what happened, but still do not write code from scratch. Each session
introduces at most one new statistical concept.

Data sometimes comes from SQLite files. The LLM handles loading these into
dataframes; learners do not write or read SQL.

## Session 1: Introduction

-   Slug: intro
-   Domain: the tutorial itself
-   Statistical concept: what statistics is for
-   Goals:
    -   Understand what this course will teach and why it matters
    -   See how researchers actually use data science tools today
    -   Articulate what LLMs can and cannot do as coding assistants
-   Content:
    -   What is data science? (turning messy observations into defensible claims)
    -   Why Python and not spreadsheets? (scale, reproducibility, sharing)
    -   What LLMs actually do when they generate code (pattern matching, not
        reasoning)
    -   Why this matters for trusting their output
    -   The social and environmental costs of LLMs
    -   What the course will build, session by session
    -   Statistics as the discipline of drawing conclusions from imperfect data:
        why every number in a research paper has uncertainty behind it
-   No coding in this session: discussion and orientation only

## Session 2: First Steps

-   Slug: llm
-   Dataset: NASA GISS Surface Temperature Analysis (GISTEMP v4),
    https://data.giss.nasa.gov/gistemp/
-   Statistical concept: mean and median
-   Goals:
    -   Launch the notebook environment and run a first code cell
    -   Prompt an LLM to read a data file and print its contents
    -   Prompt an LLM to compute and interpret the mean and median of a column
-   Content:
    -   Launching the notebook environment; creating a new notebook; running a cell
    -   Prompting an LLM to write "read a CSV and print the first five rows";
        pasting the result into a cell; running it
    -   Prompting: "compute the mean and median of the temperature column"
    -   Mean vs. median in plain English: why they differ when the data is skewed,
        and which to report depending on whether outliers matter
    -   Saving the notebook: the saved file is a record of the analysis that
        anyone (including future-you) can re-run to get the same result —
        this is what reproducibility means in practice
    -   The prompt-paste-run loop: what we will do in every session from here on

## Session 3: First Charts

-   Slug: chart
-   Dataset: NASA Exoplanet Archive Planetary Systems Composite Parameters,
    https://exoplanetarchive.ipac.caltech.edu/
-   Statistical concept: correlation
-   Goals:
    -   Prompt an LLM to create a scatter plot and save it to a file
    -   Interpret whether the chart answers the question you asked
    -   Explain what correlation means and how to read it from a scatter plot
-   Content:
    -   Why looking at data before computing statistics is essential
        (Anscombe's quartet: four datasets with identical means and variances
        but completely different shapes)
    -   Prompting: "make a scatter plot of orbital period on the x axis and
        distance on the y axis, colored by planet type, and save it as a PNG"
    -   Correlation in plain English: when one variable tends to increase as
        another increases (positive), decrease (negative), or show no pattern
    -   Prompting: "compute the correlation between orbital period and distance"
        and matching the number to what the scatter plot shows
    -   Iterating on prompts to improve the chart: log scales, axis labels,
        removing extreme outliers — each time re-running and checking the result
    -   Validation: count the points visible in the chart and compare to the
        number of rows in the dataframe — a mismatch means some data was
        silently dropped

## Session 4: Cleaning

-   Slug: clean
-   Dataset: Diabetes 130-US Hospitals for Years 1999-2008 (UCI ML Repository),
    https://archive.ics.uci.edu/dataset/296/diabetes+130-us+hospitals+for+years+1999-2008
-   Statistical concept: sampling bias
-   Goals:
    -   Prompt an LLM to find missing values and inconsistent categories
    -   Interpret before-and-after output to confirm cleaning worked
    -   Explain how missing data can make a sample unrepresentative
-   Content:
    -   Why real data is always dirty (data entry, format conversions, merges)
    -   Prompting: "show me how many missing values each column has"
    -   Prompting: "show me every distinct value in the gender column" and
        interpreting the resulting list ("M", "Male", "male", "F", "female", ...)
    -   Prompting: "normalize those values so only 'male' and 'female' appear";
        running the result; checking the distinct values again to confirm
    -   Sampling bias: if records for one patient group are missing more often
        than others, any conclusion drawn from the cleaned data may not apply
        to the full population, and the LLM has no way to warn you about this
    -   Validation: check that total row count after removing duplicates is
        smaller than before, and spot-check one removed row to confirm it
        really was a duplicate and not a legitimate record

## Session 5: Summarizing

-   Slug: summarize
-   Dataset: City of Chicago Annual Appropriations (Chicago Data Portal),
    https://data.cityofchicago.org/
-   Statistical concept: confidence intervals
-   Goals:
    -   Prompt an LLM to group data and compute aggregations
    -   Interpret a confidence interval as a measure of how certain an estimate is
    -   Sanity-check a summary against a known published figure
-   Content:
    -   What "group by" means in plain English (one row per department per year,
        not one row per spending item)
    -   Prompting: "show me total and mean spending by department for each year,
        sorted by department name"
    -   Prompting: "add a 95% confidence interval to each group mean"
    -   Confidence intervals in plain English: if we repeated this study many
        times, 95% of the intervals we built would contain the true mean — it
        is a statement about the method, not a guarantee about this one interval
    -   When two departments' confidence intervals do not overlap, their spending
        levels are probably genuinely different; when they do overlap, we cannot
        be sure
    -   Sanity-checking: finding the city's published total in the original
        budget document and confirming the LLM's sum matches

## Session 6: Tables

-   Slug: tables
-   Dataset: North American Breeding Bird Survey route-level data (USGS),
    https://www.pwrc.usgs.gov/bbs/
-   Statistical concept: spread (standard deviation and range)
-   Goals:
    -   Prompt an LLM to load tabular data and describe what it contains
    -   Interpret shape, column names, and data types
    -   Ask the LLM to compute spread and explain what it means for this data
-   Content:
    -   What a dataframe is (a table with named columns and typed data)
    -   Prompting: "load this CSV and tell me how many rows and columns it has
        and what each column contains"
    -   Reading the output: what shape, dtypes, and a sample row tell you
    -   Prompting: "compute the standard deviation and range of the count column"
    -   Standard deviation in plain English: how far a typical observation sits
        from the mean; range as the distance from smallest to largest
    -   Interpreting the result: a high standard deviation for bird counts means
        survey routes vary a lot, not that the data is wrong
    -   Validation: filter to a single known route and check that its row count
        matches the number of survey years in the dataset documentation

## Session 7: Better Prompts

-   Slug: prompts
-   Dataset: USGS National Geochemical Survey,
    https://mrdata.usgs.gov/geochem/
-   Statistical concept: probability
-   Goals:
    -   Identify what information an LLM needs to write useful data-science code
    -   Write prompts that include data shape, goal, and constraints
    -   Interpret a probability as a proportion and connect it to observed counts
-   Content:
    -   Why vague prompts produce vague code: the LLM invents column names
        it has not been told
    -   Anatomy of a useful prompt: data description (columns, types, a sample
        row) + goal + constraints (units, expected range)
    -   Prompting: "what proportion of soil samples exceed the safe lead threshold?"
    -   Probability as a proportion: if 23 of 200 samples exceed the threshold,
        the probability is 0.115, meaning about 1 in 9 — not a certainty, not a rarity
    -   Giving the LLM a two-row sample of the data in the prompt to anchor its
        column names; re-prompting when the first result is wrong
    -   Validation: compute the proportion by hand on a small subset of rows
        to confirm the LLM got the right answer before trusting it on the
        full dataset

## Session 8: Tracking Change

-   Slug: change
-   Dataset: CDC FluView national and regional influenza surveillance,
    https://gis.cdc.gov/grasp/fluview/fluportaldashboard.html
-   Statistical concept: trends and regression
-   Goals:
    -   Prompt an LLM to plot a variable over time and describe what it shows
    -   Interpret a trend line: direction, slope, and scatter around the line
    -   Distinguish a real trend from seasonal or random fluctuation
-   Content:
    -   Why researchers usually care about change, not just a single snapshot
    -   Prompting: "plot weekly influenza-like illness percentage over time
        as a line chart"
    -   Prompting: "fit a trend line to the annual peak values and show the
        slope"; interpreting the result: direction (rising or falling) and
        rate (how much per year)
    -   Regression in plain English: the line that best summarizes the overall
        direction; points scatter around it because many factors drive flu
        beyond the long-term trend
    -   Seasonal pattern vs. long-term trend: the winter spike is not the same
        as the multi-year trend; confusing them is a common mistake
    -   Validation: check that the trend line's direction matches what you
        can see by eye in the line chart — if they disagree, something is wrong

## Session 9: Joining Data

-   Slug: join
-   Dataset: NOAA Global Historical Climatology Network Daily (GHCN-D) —
    station readings file and station inventory file (separate downloads),
    https://www.ncei.noaa.gov/products/land-based-station/global-historical-climatology-network-daily
-   Statistical concept: comparing groups
-   Goals:
    -   Explain in plain English what a join does and when it is needed
    -   Prompt an LLM to join two dataframes and interpret the result
    -   Compare summary statistics across groups created by the join
-   Content:
    -   Why data arrives in separate files: readings collected by one team,
        station locations and classifications recorded by another
    -   Prompting: "combine the readings dataframe and the stations dataframe
        so each reading row also shows the station's elevation and climate zone"
    -   Checking the result: does every reading row now have an elevation?
        Are there any nulls that were not there before?
    -   Prompting: "show me the mean temperature by climate zone" — the join
        is what makes this question answerable
    -   Comparing groups in plain English: do coastal stations show different
        average temperatures than inland ones, and is the difference large
        enough to matter given the spread within each group?
    -   Validation: count rows before and after the join; a sudden increase
        means one station matched multiple readings unexpectedly

## Session 10: Telling Stories

-   Slug: stories
-   Dataset: Student Performance Data Set (Paulo Cortez, University of Minho,
    UCI ML Repository), https://archive.ics.uci.edu/dataset/320/student+performance
-   Domain: student grades, study time, and family background in Portuguese
    secondary schools
-   Statistical concept: correlation vs. causation
-   Goals:
    -   Choose chart types that match the question being asked
    -   Prompt an LLM to create bar charts, line charts, and faceted charts
    -   Explain why a correlation between two variables does not prove one
        causes the other
-   Content:
    -   Matching chart type to question: counts (bar), trends (line),
        distributions (histogram), relationships (scatter)
    -   Prompting: "make a bar chart of average final grade by weekly study
        time category, with one panel per school" and reading the result
    -   The chart shows students who study more score higher: why this does
        not prove that studying more causes higher scores (students from more
        supportive family backgrounds may both study more and score higher
        for independent reasons)
    -   Prompting to fix a misleading chart: "the y axis starts at 60; start
        it at 0 so the differences are not exaggerated"
    -   Validation: check that each panel in a faceted chart contains data
        and that the group sizes are roughly what the raw counts would predict

## Session 11: Checking Your Work

-   Slug: validate
-   Dataset: EIA Monthly Energy Review (US Energy Information Administration),
    https://www.eia.gov/totalenergy/data/monthly/
-   Domain: two tables from the same publication that report related quantities
    in different units (one in trillion BTU, one in billion kWh)
-   Statistical concept: inference and hypothesis testing
-   Goals:
    -   Verify LLM output by checking it against known values and common sense
    -   Interpret a hypothesis test result without misreading it as certainty
    -   Recognize that a confident-sounding LLM answer is not a correct answer
-   Content:
    -   The scenario: the LLM produces a comparison that is off by a factor of
        293 because it treated trillion BTU and billion kWh as the same unit
    -   Strategies that do not require reading code: check a single known row
        by hand; compare the total to a published figure; ask the LLM "what
        units did you assume for each column?"
    -   Prompting: "run a t-test to check whether electricity consumption
        differs significantly between the two regions" and reading the p-value
    -   Inference and hypothesis testing in plain English: we assume there is
        no difference (the null hypothesis), then ask how surprising our data
        would be if that were true; a small p-value means "pretty surprising",
        not "proven"
    -   Why a unit error can produce a statistically significant result that
        means nothing: significance tells you the signal is real, not that you
        measured the right thing

## Session 12: Reproducibility

-   Slug: repro
-   Dataset: NOAA Mauna Loa Atmospheric CO2 Concentration (Keeling Curve),
    https://gml.noaa.gov/ccgg/trends/data.html
-   Statistical concept: none new — consolidation of the full workflow
-   Goals:
    -   Re-run a complete analysis from a saved notebook and verify it produces
        identical output
    -   Reproduce a published scientific figure from public data and code
    -   Explain what makes an analysis reproducible and why it matters
-   Content:
    -   The replication crisis: many published findings fail to reproduce,
        often because the analysis was not saved in a runnable form
    -   What reproducibility requires: the data, the code, and the environment
        must all be available and unchanged
    -   Prompting the LLM to write a complete analysis that recreates the
        Keeling Curve (monthly CO2 at Mauna Loa from 1958 to the present)
    -   Comparing the output chart to the published NOAA figure: if they match,
        the analysis is correct and reproducible
    -   Running the notebook a second time from scratch and confirming the
        output is bit-for-bit identical
    -   Sharing the notebook: what a collaborator needs to re-run it, and
        what can silently break when they try (different package versions,
        missing data file)

## Finale: Conclusion

-   Slug: finale
-   No new content, no coding
-   Content:
    -   Review: the workflow built across sessions (prompt -> run -> interpret
        -> sanity-check -> refine -> chart -> verify)
    -   How to find help when the LLM fails: official documentation, forums,
        asking a colleague who codes
    -   The environmental and labor costs of LLMs: what we know, what we don't,
        and how to make an informed choice about when to use them
    -   Where to go next: more statistics, machine learning, reproducible
        research workflows, version control with git
